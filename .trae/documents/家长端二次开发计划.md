# SmartKBS 家长端（第四端）二次开发计划

## 一、Summary（概述）

在现有"管理员 / 教师 / 学生"三端基础上，新增**家长端**：家长账号与学生绑定后，可在 Web（手机优先响应式）上只读查看孩子的成绩错题、在校表现（积分/考勤/课堂活动）、通知公告与作业完成情况。用途为个人/演示研究，因此采用**最小可行路径**：复用现有角色体系、鉴权链路、数据接口与前端路由守卫，不引入新框架、不做推送与 IM。

## 二、Current State Analysis（现状分析）

### 角色与鉴权
- `users.role` 为整数：`ROLE_ADMIN=0 / ROLE_TEACHER=1 / ROLE_STUDENT=2`，定义于 [auth.py](file:///workspace/backend/auth.py#L304-L326)；无家长角色常量。
- 登录：[auth_router.py](file:///workspace/backend/api/auth_router.py#L80-L114) 读 `users.role` 生成 JWT，并映射为字符串 `admin/teacher/student` 返回给前端。
- JWT 校验时从数据库重读 role 写入 payload（[auth.py](file:///workspace/backend/auth.py#L114-L149)），权限以数据库为准。

### 前端三端分流
- [App.tsx](file:///workspace/frontend/src/App.tsx#L151-L211) 按 `user.role === 'student'|'teacher'|'admin'` 分流路由，含 `RequireRole` 路由守卫（[App.tsx](file:///workspace/frontend/src/App.tsx#L17-L39)）。
- 侧边菜单在 [AppLayout.tsx](file:///workspace/frontend/src/components/AppLayout.tsx#L62-L165) 硬编码构建 `studentMenu` / `teacherMenu`，无家长菜单。
- 登录跳转：登录后按 `user.role` 路由（Login 页面）。

### 数据模型
- 数据库为 SQLite 裸 SQL，建表集中在 [database.py](file:///workspace/backend/database.py)，迁移在 `backend/migrations/` 启动时执行。
- 学生归属 `classes`；**无 guardian 相关字段/表**，需新增绑定关系。
- 家长需要的数据接口（成绩、错题本、积分、通知、作业）已存在"按学生查询"的实现（score_router、wrong_book_router、reward_router、notification_router、practice/homework 相关），家长端可**复用学生端接口**（校验绑定关系后放行）或新增薄包装接口。

### 项目约定
- 后端一业务域一 router 文件于 `backend/api/`，在 [main.py](file:///workspace/backend/main.py#L251-L306) 注册 `/api/<域>` 前缀。
- 前端新增页面：`frontend/src/pages/` 加页面 → `App.tsx` 挂路由 → `AppLayout.tsx` 加菜单。
- 项目无自动化测试；验证靠 `npm run lint`、`tsc -b`、手动跑通。
- 敏感配置走 `.env`。

## 四、Proposed Changes（改造方案）

### 阶段 A：后端角色与绑定关系

**A1. 角色常量扩展** — [auth.py](file:///workspace/backend/auth.py)
- 新增 `ROLE_PARENT = 3`；相关角色判断处补充家长分支。

**A2. 登录映射扩展** — [auth_router.py](file:///workspace/backend/api/auth_router.py)
- `role_val` 映射增加 `3 -> 'parent'`；登录响应与 JWT payload 携带 `parent`。

**A3. 数据库迁移** — `backend/migrations/` 新增迁移脚本（沿用现有迁移的命名与执行方式，参考现有迁移文件写法）
- 新表 `student_guardians(id, student_user_id, guardian_user_id, relation, created_at)`，唯一约束 `(student_user_id, guardian_user_id)`，建索引 `guardian_user_id`。
- 用户管理可用：家长账号 `users.role=3` 由管理员创建（复用现有创建用户流程，`role` 输入允许 3）。

**A4. 绑定管理接口** — `backend/api/users_router.py`（管理员域）
- 列出某学生的家长 / 为某学生添加或移除家长绑定；仅 `ROLE_ADMIN` 可操作。
- 家长登录后返回其绑定的学生列表 `[{user_id, name, class_name}]`（新增 `GET /api/parent/students` 或并入登录响应，取实现简单者：并入 `users_router` 新端点）。

**A5. 家长域接口** — 新建 `backend/api/parent_router.py`，在 [main.py](file:///workspace/backend/main.py) 注册 `prefix="/api/parent"`，统一挂 `require_auth`
- `GET /api/parent/overview?student_id=` — 聚合首页数据（成绩概要、积分/称号、未读通知数）。
- `GET /api/parent/scores?student_id=`、`GET /api/parent/wrong-book?student_id=`、`GET /api/parent/attendance?student_id=`、`GET /api/parent/notifications?student_id=`、`GET /api/parent/homework?student_id=` — 内部复用学生端已有 service/查询逻辑，**每个请求必须校验 `student_id` 属于当前家长的绑定学生**（写一个依赖项 `verify_guardian_binding`）。

### 阶段 B：前端家长端

**B1. 类型与请求层** — `frontend/src/types/`、`frontend/src/api/`
- 增加 `role: 'parent'` 联合类型；新增 `parent.ts` 请求模块（overview/scores/wrong-book/attendance/notifications/homework）。

**B2. 路由与守卫** — [App.tsx](file:///workspace/frontend/src/App.tsx)
- 新增 `user.role === 'parent'` 分支：`/parent` 概览、`/parent/scores`、`/parent/wrong-book`、`/parent/attendance`、`/parent/notifications`、`/parent/homework`，全部走 `RequireRole parent`。

**B3. 家长端页面** — `frontend/src/pages/parent/`（新建目录）
- `ParentHome.tsx`（孩子切换器 + 概览卡片）、`ParentScores.tsx`、`ParentWrongBook.tsx`、`ParentAttendance.tsx`、`ParentNotifications.tsx`、`ParentHomework.tsx`。
- 手机优先：复用 antd 组件 + 现有移动端样式约定（项目已有 `frontend/mobile-qa` 与响应式处理，实现时先参考学生端页面在窄屏下的做法）；多孩子用顶部选择器切换，所有请求带 `student_id`。

**B4. 菜单与布局** — [AppLayout.tsx](file:///workspace/frontend/src/components/AppLayout.tsx)
- 新增 `parentMenu`（概览/成绩/错题/考勤/通知/作业），家长角色走该菜单；沿用现有布局容器，窄屏折叠行为与学生端一致。

**B5. 登录跳转** — Login 页面
- 登录成功后 `role==='parent'` 跳转 `/parent`。

### 阶段 C：文档同步
- 更新 README 的"权限总览/角色"相关小节（仅改角色描述处，避免大改）。

## 五、Assumptions & Decisions（假设与决策）

1. 绑定方式 = 管理员后台绑定；若你要邀请码自助绑定，阶段 A3/A4 换方案即可，A/B 其余不变。
2. 第一期家长端为**只读**，不新增家长写操作（除切换孩子）。
3. 不做移动端独立 App / 小程序；浏览器响应式即可。
4. 考勤数据源：点名 `rollcall_router` 有按学生记录，家长端"考勤"读该数据；若字段不足，先展示已有记录，不新建考勤表。
5. 与现有三端零侵入：所有改动为增量分支（`dev/2026-10-29`），不修改既有路由行为（仅在角色枚举与菜单构建处扩展）。
6. 项目无测试框架，本任务不引入（保持项目现状），验证以 lint/build + 手动接口联调为准。

## 六、Verification（验收步骤）

1. 后端：启动 `python -m backend.main`（或项目现有启动命令），确认迁移执行成功、`/api/parent/*` 注册无报错。
2. 接口：管理员创建家长账号 → 绑定学生 → 家长登录拿 token → 逐个调用 `/api/parent/*` 返回正确数据；**越权用例**：家长 A 请求未绑定学生 `student_id` 必须返回 403。
3. 前端：`npm run lint`、`tsc -b && vite build` 通过。
4. 手动：浏览器以家长账号登录 → 落在 `/parent` → 六个菜单页均可用；窄屏（375px）布局正常；学生/教师/管理员三端回归不受影响（登录、首页、菜单正常）。
5. 文档：README 角色描述已同步。
